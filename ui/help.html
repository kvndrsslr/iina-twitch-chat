Twitch

Shows Twitch chat in the video overlay, always bound to the stream that is playing, and browses Twitch from the Twitch sidebar tab. Configuration is shared with twitch-tui: ~/.config/twt/config.toml and ~/.config/twt/filters.txt. The plugin works with no configuration file at all, and chat is read-only: there is no message composer.

Plugin menu

IINA only shows the first five first-level items of a plugin menu, so the plugin uses four and keeps the Config entries in the Config submenu.

Connect / DisconnectOpen or close the IRC connection.
Toggle Twitch Overlay ⌘⇧TShow or hide the chat on top of the video.
Show Twitch Sidebar ⌘⇧BOpen IINA's sidebar on the Twitch tab.
Open Twitch Window ⌘⇧WOpen the standalone Twitch browser window; works with no media and no player window.
Config ▸ Reload ConfigRe-read config.toml and filters.txt.
Config ▸ Open Config FolderReveal the folder of the config file that was found in the Finder.
Config ▸ Open Help / READMEOpen this page.

Known IINA behaviour. IINA rebuilds a plugin's menu (and its key equivalents) only when the Plugin menu is opened, when a plugin asks for a rebuild, or once at the end of app launch — not when a window becomes key or closes. While a non-player window is key, including this plugin's standalone Twitch window, IINA falls back to the first player window, so Toggle Twitch Overlay and Show Twitch Sidebar act on that window (or do nothing if it is gone); Open Twitch Window (⌘⇧W) is global and keeps working. Opening the Plugin menu once re-binds the per-player items to the window in front.

Standalone Twitch window

Plugin ▸ Open Twitch Window (⌘⇧W) opens the browser in IINA's own standalone window. A sidebar cannot exist without a player window, so this is the way to browse Twitch with nothing loaded. It is browse-only: the five browse tabs, no chat (the IRC client needs a player channel) and no Settings pane. Channel and category rows navigate inside the window; the Watch button and VOD rows open a new player window, since there is no current player to load into.

With the Startup preference auto_open_browser on (default off), the window opens itself once per launch when IINA starts with nothing playing: it waits about 2.5 seconds, does not open if media arrives during that window (opening a file or a restored session cancels it), and leaves an already-open window alone. ⌘⇧W opens it manually in any state; the switch takes effect on the next launch.

Switching streams

Opening a stream/VOD into the current window replaces the media through mpv loadfile … replace, so IINA's Loading Media… window does not appear. IINA's own title/history/“now playing” bookkeeping does not update for that load. If the load fails, the plugin notices after a short grace period, shows the URL could not be opened and releases the channel so chat goes idle instead of showing the previous stream. Opening in a new window still uses IINA's loader.

Where chat appears

  • Only in the video overlay. It has a one-line connection/channel header and the message list, with no chat controls, so the video keeps every mouse event outside the panel.
  • Only on a Twitch video. The panel is shown while chat is bound to the playing media, so any other video leaves it hidden; ⌘⇧T then reports Twitch Chat is only available on Twitch videos. The visibility preference is kept, so the overlay returns with the next Twitch stream.
  • The sidebar does not show chat, has no composer, no message list and no channel switcher. Its web view still hosts the IRC connection in the background, so chat keeps flowing while the overlay is hidden.
  • The panel itself responds to the mouse (its header for moving, its edges and corners for resizing, and scrolling); everything outside it stays click-through.

Chat follows the stream

Chat is bound to the channel the plugin detects in the media that is playing:

  • A twitch.tv/<login> URL anywhere in the video URL, the mpv path/filename/media-title or a playlist entry wins — including the m., go. and player. forms and player.twitch.tv/?channel=<login>. Reserved paths such as videos, clips, directory and settings are skipped.
  • Only when no URL matches is the title used as a fallback, and only when the same media is demonstrably Twitch-sourced (twitch.tv, ttvnw.net or twitch.com in the URL, path, file name or media title): ohnePixel — VITY vs LOUD [GRAND FINAL] becomes #ohnepixel, while a YouTube video called Bob - highlights never joins #bob, and titles that reduce to a stopword (vod, live, highlights, …) are rejected.
  • Detect the channel of the playing video (auto_join, on by default) is the only switch. With it off the plugin never joins automatically. Detection itself is always automatic: it runs on every file load.
  • There is no config channel, no manual join and no remembered channel. A video without a Twitch channel releases the previous one and chat goes idle. Each newly loaded file re-evaluates the choice.
  • The plugin announces the join with Twitch: joined #<login> (from the playing video) and logs one decision line (channel decision: detected #x from …). The overlay header shows #<channel>.
  • Limitation: a twitch.tv/videos/<id> VOD URL carries no channel name, so there the title heuristic is the only signal for binding live chat.

Sidebar: browse and settings

The sidebar has six tabs: Following, Top, Categories, Search, Videos and Settings. Browsing needs an OAuth token (the plugin's API proxy has no anonymous mode); without one the pane shows a No token explanation with Retry. Following additionally needs user:read:follows and Videos uses the same followed-channel list.

  • Each tab keeps its own history, its own loaded data and its own search text. Switching tabs neither reloads nor refetches; Back and Escape pop only the active tab's history, and the refresh button refetches only the active tab. The tab strip scrolls sideways rather than wrapping.
  • Following: live channels first by viewer count (highest first, ties by name), then offline channels by name A→Z. The comparison is case-insensitive and applied to the whole accumulated list, so pagination cannot leave an unsorted tail.
  • Top: Twitch's top live streams. A row opens the channel page; its Watch button opens the stream.
  • Categories: Twitch's top categories, with a search field (/helix/search/categories). Category rows show no viewer count — the /helix/games/top payload has none and there is no bounded API call that yields a category total — and keep Twitch's own popularity order. Opening one lists its live streams.
  • Search: channel search (/helix/search/channels). A result opens the channel page, whose Videos section holds that channel's VODs.
  • Videos: recent videos from the channels you follow, newest first, with a filter over title, channel name and login. The filter only ever considers these recent videos — typing a channel name never pulls that channel's videos through a channel search. Helix has no VOD text search, so this is not a search of all of Twitch.
  • A VOD whose thumbnail is missing/empty or still processing (_404/404_processing_, never requested) uses the live stream's thumbnail while the channel is broadcasting, otherwise a placeholder. If a Twitch-hosted VOD thumbnail still fails to load, the box swaps once to the live preview when one is available, then gives up. Images are only loaded from Twitch's own image hosts.
  • A VOD row, or the Watch button on a live row, opens the stream/video in the current player window; ⌘-click or middle-click opens it in a new player window. Clicking a channel/category row navigates inside the sidebar. Playback itself is resolved by IINA/yt-dlp/streamlink.
  • The connection indicator is a pinned footer at the bottom of the sidebar; only the tab content scrolls.
  • Settings — palette, theme, timestamps and format, usernames, mention highlighting, badges, channel title, the four emote toggles, message cap, render delay and the message/username filter switches. Every control defaults to “Use config”.
  • The same overrides are also in IINA → Settings → Twitch.

Chat history

The plugin keeps the last 50 messages of each channel (up to 20 channels, at most 512 KB) in its data folder, so a channel you return to is not empty. Returning to a channel shows those messages above the live ones. With Pre-fill the last 50 messages from a community recent-messages service enabled (default off), a channel visited for the first time is pre-filled from recent-messages.robotty.de; that request carries only the public channel name, never your OAuth token. Twitch itself offers no chat-history API.

VOD chat replay

A VOD's chat is replayed from Twitch's undocumented GQL endpoint (VideoCommentsByOffsetOrCursor, public web client id kimne78kx3ncx6brgo4mv6wki5h1ko, no Authorization header). There is no supported Twitch API for VOD chat. Comments are fetched forward from the playhead (first by offset stepping - the next request starts just past the newest comment of the last page, which overlaps the pages and is deduped by comment id), only one request is in flight at a time and requests are at least 250 ms apart; a backwards seek or a jump of more than 15 s forward resets the buffer and refetches. A 1 s tick emits comments as the playhead reaches them. Live chat is suppressed while a VOD plays, the overlay is cleared when replay starts and stops, and the IRC socket stays connected for room-id and emote sets. vod_chat_replay (on by default) disables the replay; when it fails you get one warning, the OSD VOD chat replay unavailable, and no chat — the plugin stays in VOD mode so live chat cannot leak in, and a seek retries. This uses an undocumented endpoint, so it may stop working if Twitch changes it.

A replayed comment shows one time: the offset into the VOD (for example 10:18), the point in the broadcast where it was originally sent. The original wall-clock time is not recoverable from the data the plugin has — a replay event carries only the offset, and its timestamp is the replay moment — so the offset is the canonical original time. Live rows keep their own single timestamp.

Overlay layout

The overlay is moved and resized directly, with nothing to reveal and nothing that appears or disappears:

  • Move — drag the panel by its header. There is no handle: the cursor becomes a grab hand over the header and a closed hand while you drag.
  • Resize — drag any edge or corner. Each one shows its directional cursor (the zones themselves are invisible; the cursor is the only affordance). Interacting with the controls never changes the overlay's size.
  • Anchoring — the panel remembers which corner of the video it is nearest to, so a resized video window keeps its distances. It only switches corners once the panel's centre passes the video centre by a margin (10 % of the viewport on that axis), so it does not flip while you nudge it across the middle. Resizing keeps the anchored edges still and moves only the edge(s) you drag, with a 220 × 120 minimum and the panel always inside the video.
  • Escape cancels a drag or resize; the layout is saved per channel.

The panel (and only the panel) responds to the mouse while the overlay is visible; everything outside it is click-through, so the video keeps every other mouse event. The overlay reports the geometry while a gesture is in flight and the plugin stores each report immediately, writing the preference once the gesture pauses.

The arrangement is remembered per channel — the channel it was arranged in is the one it is restored for, and with no channel bound it is stored as default. The most recent 50 channels are kept. The stored layouts live in the overlay_layouts preference (IINA → Settings → Twitch); a missing or unreadable value falls back to the default position. An older {x, y, w, h} layout is still read as the top-left anchored position and rewritten in the new anchored shape on the next save; a stale overlay_layout_locked key is ignored. The bundle identifier is unchanged, so existing preferences and cached chat history survive the rename.

Tokens

A token is optional: chat connects anonymously and read-only without one. When present (from [twitch] token in config.toml, or the token you save in IINA → Settings → Twitch, stored in the macOS Keychain), it authenticates the IRC connection and lets the sidebar use Twitch's API. The plugin validates it itself and no web view makes Twitch API calls directly: the sidebar asks the plugin, which adds the credentials, and only an allow-list of Helix paths plus /identity is served. The token is never shown in the Twitch browser, never sent to the overlay and never logged.

Troubleshooting

  • Window → Log Viewer shows everything the plugin logs (global - Twitch and player… - Twitch).
  • Plugin → Developer Tool (IINA 1.4+) evaluates JavaScript in the plugin's context.
  • No chat / nothing joins: the playing video must carry a Twitch channel (URL, path or Twitch-sourced title). Detection runs on every file load; the log line channel decision: … says what was found. Check that auto_join is on.
  • Following is empty or explains a missing permission: the saved token needs the user:read:follows scope. Re-authorise the token and press *Retry*.
  • A new player window does not open: IINA must expose its global entry (iina.global.createPlayerInstance); the log says no global entry in this build otherwise. Stream playback also needs yt-dlp or streamlink configured in IINA.
  • VOD chat is empty: VOD replay uses Twitch's undocumented endpoint and can fail without notice; check that vod_chat_replay is on.
  • Third-party emotes need their toggles on and the plugin's network permission for the API hosts api.betterttv.net, 7tv.io (and api.7tv.app) and api.frankerfacez.com, plus the image CDNs cdn.betterttv.net, cdn.7tv.app and cdn.frankerfacez.com.
  • Badges, Twitch emotes and the IRC endpoint need *.jtvnw.net, *.twitch.tv and irc-ws.chat.twitch.tv; the Twitch API proxy also uses api.twitch.tv and id.twitch.tv (both covered by *.twitch.tv).
